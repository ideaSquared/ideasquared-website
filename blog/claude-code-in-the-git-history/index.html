What working with Claude Code looks like in our git history.

We use Claude Code every day. Instead of describing that, we counted what git can prove, in four repos, as of 28 November 2026. Then we list what git cannot tell you.

  • By Alex Jenkinson, with support from Claude
  • 28 Nov 2026
  • 3 min read

How we counted

Every number below comes from git log --all in four repos: agent-idea, shipper, eng and ideasquared-website. Counts are as of 28 November 2026. Where a number depends on a choice, we say which.

The repos start on different dates. ideasquared-website’s first commit is 14 August 2026. shipper’s is 13 November. agent-idea’s and eng’s are 14 November. Last commits are 24 November for the first three and 28 November for the website.

Commits and trailers

Commits per repo, merges included: agent-idea 64, shipper 139, eng 114 and ideasquared-website 201. That is 518 in all.

Of those, 143 are merge commits and 375 are not. Of the 375, 356 carry a Claude-Session: trailer in the commit message: 46 of 47 in agent-idea, 97 of 98 in shipper, 79 of 81 in eng and 134 of 149 in the website. The other 19 have no trailer.

Those trailers hold 69 distinct session links across the four repos. Some sessions touched more than one repo, so adding the per-repo counts would give 85, not 69.

Author names

Git records an author name on each commit. Among the 375 non-merge commits, 343 have an author name that is Claude (one of them under a second Claude name) and 32 are authored as Alex Jenkinson. Per repo, Alex authored 12 in agent-idea, 2 in shipper, 2 in eng and 16 in the website.

This is a count of names, not of work. It says who ran the commit, not who thought of the change or edited the result.

Branches and merges

Of the 143 merge commits, 135 are authored as Alex Jenkinson and committed by GitHub. Another 8 are authored by Claude, and their subjects show changes from main being merged into a branch.

The pull request merges are the clearest trace. We counted merge commits whose subject names a claude/* branch: 131 pull requests (16 in agent-idea, 37 in shipper, 29 in eng, 49 in the website). Four more pull request merges name another branch, such as fix/venv-readiness.

That is as far as we take it. A merge commit shows that Alex’s account merged the pull request, on that date. It does not show what he checked first.

Rules in every repo

Each repo carries a CLAUDE.md: at the root in agent-idea, shipper and eng, and under .claude/ in the website. It holds the rules for working there: commands to run before a change is done, what to test, what never to log. The rules are decided by us.

All four repos also carry .claude/skills/logging/SKILL.md, and the file is identical in each. We checked with md5sum: all four print 5a51e155309144a277f41d3fe369d784. agent-idea holds the canonical copy. The other three received it by copy: shipper and eng on 14 November, the website on 22 November. For more on how rules travel between repos, see one rulebook, every repo.

Review-driven fixes

We looked for commits whose own message says review caused the change. There are six:

  • agent-idea, 14 November: “close three sanitiser gaps found in review”;
  • agent-idea, 15 November: “close review leaks in the ADS errors route and tunnel guide”;
  • eng, 14 November: “address review findings in the installers and CLI”;
  • eng, 22 November, and again on 24 November: two “address review” commits on the engineering standards;
  • ideasquared-website, 9 October: “correct three factual errors flagged in review”.

More fixes were probably prompted by review without saying so. We only count the ones that say it. The posts what review found and every leak becomes a test cover some of them.

What the history doesn’t show

  • No speed or productivity baseline. We have no earlier period without Claude Code to compare against, so we make no claim about faster or slower.
  • Nothing on quality or defect rates. Commit counts say nothing about whether the code is good. Fix commits exist, but we have no count of bugs that were never found.
  • Not how much a person edited before merging. A commit holds the end result, not the conversation that led to it.
  • Not who reviewed. A merge shows who pressed the button. It does not show who read the diff, or how closely.
  • Not a share of the code. Author names and trailers count commits. We do not know, and will not state, what fraction of the code came from whom.

What we learned

  • Trailers make the record honest. A Claude-Session: line on a commit lets anyone count the sessions behind a repo, and we never have to rely on memory.
  • Put the rules in the repo. A CLAUDE.md and one shared skill file are checkable with md5sum. A rule held in someone’s head is not.
  • Say what the data cannot say. The history proves how often and where. It cannot prove that the work is better, faster or well reviewed.
