Studio tools

The tools that run the studio.

A one-person studio has no platform team, so we wrote one down in code. Four tools deploy every venture, keep personal data out of the logs, and set up a new machine with one command. All four are public on GitHub.

How they fit together

One path from laptop to live.

Each tool does one job. The safety rules live inside the tools, not in a document someone has to remember.

Set up
eng installs what a machine needs, clones every repo and installs ship and idea.
Write logs
@ideasquared/log is how every server writes a log line, with no personal data.
Deploy
shipper deploys, checks the result and rolls back if it fails.
Read logs
Agent Idea reads the logs back, sanitised, for people and for Claude.
The four tools

What each one does.

All four were built in November 2026, for every ideaSquared product.

  • ship

    shipper

    One way to deploy every product.

    • Each repo describes its deploy in a short ship.yaml. One shared GitHub Actions workflow does the rest.
    • It won’t deploy a commit whose checks failed, or one older than what is live.
    • A health check runs after every deploy. If it fails, the deploy rolls back.
    • ship status all shows what is live everywhere. ship diff, ship rollback, ship freeze and ship doctor cover the rest.
    How we built itSource on GitHubMIT licence
  • idea

    Agent Idea

    Sanitised logs, for people and for LLMs.

    • Reads Cloudflare Workers Logs, GitHub Actions runs, Loki and GlitchTip through one command.
    • Only fields on an allowlist come back. Emails, tokens, IP addresses and card numbers are scrubbed, and ids become anonymous tags.
    • You only see a product’s logs if you are in its GitHub team.
    • idea mcp lets Claude Code read the same sanitised logs as tools, so an AI assistant never sees raw data.
    How we built itSource on GitHub
  • @ideasquared/log

    The logger

    A logger that refuses personal data.

    • Modelled on Monzo’s slog. Every service declares the fields it may log.
    • The message must be a fixed string, so `sent to ${email}` doesn’t compile.
    • Declaring a field such as email, ip or token throws. Log an id instead.
    • Server code that calls console directly fails CI.
    How we built itSource on GitHub
  • eng

    eng

    One command to set up a developer machine.

    • One installer for macOS, Linux and Windows. It installs only what is missing and is safe to run again.
    • Signs you in to GitHub, clones every repo you can see and installs their dependencies.
    • Running eng on its own opens a menu over deploys, logs and ops. Each session is fixed to staging or production, so a stray command can’t hit the wrong one.
    • It also holds the engineering standards every ideaSquared repo follows.
    How we built itSource on GitHubMIT licence
Why build our own

Each venture starts further along.

A new venture shouldn’t have to work out deploys, logging and machine setup again. It adds a ship.yaml, uses the logger, and gets the rest on day one.

Safety in the tool
A rule the tool enforces can’t be forgotten at 11pm on a weeknight.
Privacy by default
Personal data is stopped when a log is written, and again when it is read.
Small and boring
Plain TypeScript on Cloudflare Workers and GitHub Actions. Nothing new to host.
In the open
The code is public, and the posts below say what went wrong along the way.
