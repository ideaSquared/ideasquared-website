AdoptDontShop 18 Jul 2026

Security: authentication hardened across six attack surfaces.

Six authentication-layer improvements shipped today. The 2FA setup flow now stores the pending secret encrypted server-side; an attacker with a temporary access token can no longer inject their own authenticator app and lock the real account holder out permanently. The one-time code used to confirm 2FA enrolment can no longer be replayed at the very next sign-in within its 30-second window. Locked, suspended or deactivated accounts now return the same error as a wrong password — account status can no longer be probed by guessing email addresses. Staff invitation links are now rate-limited per IP and per token, closing a brute-force path that could have silently created accounts and granted rescue-staff membership. Event image and virtual-meeting-link URLs are validated to reject javascript: and data: schemes at the gateway boundary. Error responses from the API no longer include internal infrastructure detail such as table names or service hostnames.

AdoptDontShop 18 Jul 2026

Security: gateway and infrastructure hardening.

Server access logs no longer record URL query parameters, which can contain session signatures or other sensitive values. HTTP security headers are now consistent between the API gateway and the nginx edge, eliminating the possibility of a browser seeing conflicting instructions. Docker build images for all services are pinned to immutable content digests with a CI gate enforcing the rule. Grafana monitoring now requires a strong admin password and has anonymous access disabled by default. The deployment pipeline routes workflow inputs through environment variables rather than direct shell interpolation, closing a script-injection footgun in CI.

AdoptDontShop 17 Jul 2026

Security: 2FA backup codes hardened; password oracle closed.

Backup codes now appear exactly once in a confirm-before-dismiss panel at 2FA enrolment — you must acknowledge you’ve saved them before the panel closes, replacing the old persistent grid with no confirmation step. Regenerating backup codes now requires a valid live authenticator code, so a stolen browser session alone can no longer replace your recovery path. A persistent warning now appears when the last code is consumed at sign-in, prompting immediate regeneration before self-service recovery is exhausted. Separately, a correct password submitted against an unverified account previously returned a distinct response that bypassed the failed-attempt counter; the response is now indistinguishable from a wrong password and the same lockout logic applies.

AdoptDontShop 16 Jul 2026

Security: 2FA backup code usage made race-safe.

Two simultaneous sign-in attempts using the same 2FA backup code could previously both succeed. The check-and-consume step is now a single atomic database operation, so a leaked or stolen backup code can only ever be accepted once.

AdoptDontShop 15 Jul 2026

Security: session tokens moved to HttpOnly cookies.

Authentication tokens are no longer stored in browser localStorage. They now live in HttpOnly server-set cookies that JavaScript cannot read, eliminating the class of attack where a cross-site scripting vulnerability could silently steal your session. Any tokens stored in localStorage from before this update are automatically cleared on first page load after the change.

AdoptDontShop 14 Jul 2026

Security: 2FA recovery codes and CSRF protection.

Accounts with two-factor authentication now receive 10 single-use recovery codes at enrolment, letting you regain access without staff intervention if you lose your authenticator app. Codes are stored as one-way hashes only; a fresh set can be generated at any time and immediately invalidates the old ones. All state-changing API requests are now protected by a CSRF double-submit token validated by the gateway, blocking cross-site request forgery attacks from third-party pages.

AdoptDontShop 13 Jul 2026

Security: 2FA secrets encrypted at rest; data access and policy race hardened.

Two-factor TOTP secrets are now stored encrypted (AES-256-GCM); a database exposure can no longer produce usable offline bypass tokens, and an accepted authenticator code cannot be replayed within its 30-second window. The IP address and user agent recorded against each session are now read from the verified gateway connection rather than caller-supplied headers. Supporting document URLs on adoption applications are validated at upload, preventing crafted links (javascript: or arbitrary external hosts) from being stored and later rendered in the rescue reviewer interface. Platform-wide user statistics are restricted to administrators only. A concurrent-save race in rescue adoption policy settings is closed — two simultaneous saves can no longer silently overwrite each other.

AdoptDontShop 11 Jul 2026

Report reliability; chat attachment preview and identity controls hardened.

A single failing analytics widget no longer aborts an entire rescue report page — each widget now reports its own status independently, so the rest of the dashboard still loads. The inline chat attachment viewer no longer routes PDFs through an external proxy service, which was leaking private attachment URLs to a third party; previews are now sandboxed natively in the browser, and non-PDF files become direct downloads. Support tickets now always derive the requester’s identity from the authenticated session; chat sessions verify the relationship between parties before opening; and only moderators or rescue staff can close a conversation.

AdoptDontShop 10 Jul 2026

Platform-wide security and infrastructure hardening.

When a reused or compromised refresh token is detected, every token in that session family is now revoked immediately and active access tokens are invalidated — an attacker who obtained a token can no longer remain signed in after detection. Event attendance rates in the rescue dashboard were always reporting 0% due to a stale column; rates now reflect real check-in counts. Login attempts are now rate-limited per email address as well as per IP, closing a distributed credential-guessing attack. The gateway no longer trusts a caller-supplied X-Forwarded-For header for IP resolution, closing an identity-rotation bypass. Database and upload backups are now encrypted at rest. Concurrent WebSocket connections per account are capped to prevent amplification abuse. Production containers run with a read-only filesystem and as a non-root user. The Redis password must now be at least 32 characters — placeholder values are rejected at startup. All CI workflow permissions are scoped to least-privilege.

AdoptDontShop 9 Jul 2026

Security: event data isolation, GDPR deletion and role escalation all patched.

A scoping gap in the events system meant rescue staff with event-read access but no linked rescue could inadvertently see attendee names and emails belonging to other organisations’ events; all event endpoints now enforce strict per-rescue isolation. A regression introduced by an earlier database migration had caused account-deletion requests (GDPR erasure) to fail silently, leaving personal data in place and sessions valid; deletion now completes correctly across all associated data. A gap in the admin user-update path allowed admin accounts to escalate their own or others’ roles to super-admin level without the correct authorisation checks; role changes now require the same strict guards as account creation.

AdoptDontShop 1 Jul 2026

API reliability restored; session security hardened; cold-start errors fixed.

A sweep of the API gateway resolved schema issues that were causing list endpoints to mis-serialise data, some DELETE and POST routes to reject valid requests, and the top-picks endpoint to return malformed responses — all gateway tests now pass. Refresh tokens are now stored as one-way hashes; a database exposure can no longer be used to impersonate an active session. The adopter portal, rescue dashboard and admin panel no longer return errors for around 40 seconds after a cold boot — all three now wait for the API gateway to become healthy before serving.

Separately, account profile changes that were silently failing due to a routing mismatch now save correctly.

Adoption applications now derive the applicant’s identity exclusively from the authenticated session — a body-level override that could previously be used to submit an application as a different user has been removed.

Operating principles · Journal

How this page is kept honest.

Within 24 hours

Every shipped feature gets a changelog line within twenty-four hours of going live.

Customer-facing language

Written for the people who use the product, not the engineers who built it. No commit-message jargon.

Workflow-breaking only

Bugs noteworthy enough to break a workflow get listed. Trivial fixes don’t clutter the page.
