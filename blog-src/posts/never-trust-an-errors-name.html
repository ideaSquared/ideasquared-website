What the package is

@ideasquared/ops lives in the Agent Idea repo, under packages/ops. It is a shared contract for a product’s admin commands: a catalogue of commands, a way to preview a write, and a way to run it. The server half is a small handler that uses only Web Request and Response. The client half is what eng uses. For the client side, and how eng ops got its shape, see building eng.

Admin commands run with real power, and their errors can hold real data. So most of what we did on 15 November was about what happens when a handler fails.

Log the type, not the message

A handler’s error message and stack can carry personal data, arguments or tokens. @ideasquared/log copies both. So in 5a859e6 the failure line stopped receiving the real error. It gets a stand-in with a fixed message and only the original’s type as its name:

function sanitisedCause(cause: unknown): Error {
  const name = cause instanceof Error && /^[A-Za-z][A-Za-z0-9_]{0,63}$/.test(cause.name) ? cause.name : 'UnknownError';
  const safe = new Error('handler threw');
  safe.name = name;
  return safe;
}

That looks safe, and it was wrong. Error.name is a writable string. Code can set it to anything that matches a pattern, and a name made of letters, digits and underscores can hold an identifier or a token as easily as a type.

A fixed list

The fix (f75c73d) replaced the pattern with a list. Only a known type is kept. Everything else is logged as UnknownError:

const KNOWN_ERROR_NAMES: ReadonlySet<string> = new Set([
  'Error', 'TypeError', 'RangeError', 'ReferenceError', 'SyntaxError',
  'URIError', 'EvalError', 'AggregateError', 'AbortError', 'TimeoutError',
  'ZodError', 'OpsError',
]);

The tests set the name to a made-up person, a made-up token and a made-up account id, then check the serialised log:

it.each(['alex', 'ghp_SYNTHETIC_TOKEN_123', 'acct_private_42'])(
  'replaces a made-up name (%s) with UnknownError', ...)

Two more tests keep it honest. A real TypeError keeps its name, even when its message is an email address that must not appear. And a thrown value that is not an error at all, such as a string, becomes UnknownError.

A logger must never change the response

The same commit (5a859e6) dealt with a different failure. If the logger throws, because its sink is down, the naive handler throws too. For a read that is only an annoyance. For a write that already ran, it returns a 500, the caller retries, and the write happens twice.

The log call is now wrapped. If it throws, the handler carries on and answers as if nothing happened:

try {
  if (!failure) logger.info('ops command ran', fields);
  else if (failure.code === 'internal') logger.error('ops command failed', fields, sanitisedCause(cause));
  else logger.warn('ops command rejected', fields);
} catch {
  // Nothing to do: the response below is what matters.
}

Two tests use a logger whose every method throws. A write that ran is still reported as ran, with a 200. A failing command still answers the contract’s generic 500.

Choosing who may call

Version 0.2.0 (9857e21, merged in 528a254) made the access check pluggable. You give createOpsHandler exactly one of two things: repo, for the built-in write-access check, or authorize, your own check. Neither, or both, is an error at startup. A ready-made checkTeamMembership covers the common case of a GitHub team.

A custom check is new code that can throw, so 2b72d87 added a rule. An OpsError thrown by authorize used to keep its code and message on the way out. Now anything the authoriser throws becomes the generic 500, and only the error’s type is logged. The test throws an OpsError whose message holds an email and a token, and checks that neither the response nor the log contains them.

What we learned

  • A string you did not choose is not safe. An error’s name can be set by any code. Check it against a list you wrote.
  • Logging is a side effect, so contain it. A failed log write must not change what the caller is told, least of all after a write has happened.
  • Extension points need the same rules as the core. A custom authoriser got the same treatment as a handler: generic message out, type only in the log.
