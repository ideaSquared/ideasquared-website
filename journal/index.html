AdoptDontShop 4 Aug 2026

Field-level permissions enforced; private uploads move to signed URLs; live sessions cut off on logout.

Three access-control fixes shipped together. The field-level permission system that governs which parts of a rescue record each role can see or edit is now enforced at the API — rescue records are masked on read and write-guarded by the caller’s role, where before the controls existed only as configuration. Private application documents are no longer served directly: they’re reachable only through short-lived, per-request signed URLs issued after an authorisation check, and the storage layer fails closed if signing isn’t configured. Real-time chat and notification sockets now revalidate on logout, token revocation or account suspension, so a signed-out or suspended session is disconnected within seconds instead of streaming on. The analytics ingestion endpoints were hardened to strip tokens from logged URLs, and a further batch of dependency advisories was patched the same day.

AdoptDontShop 2 Aug 2026

Backend authorisation hardening: adoption-outcome privacy and analytics token leaks closed.

A logged-in adopter could previously probe whether any specific person had ever been approved for adoption — the adoption-outcome count was gated on a permission every adopter holds and would answer for a single individual. That endpoint is now restricted to admin reporting and enforces a minimum cohort size, so it can never return a per-person answer. Alongside it, a broader sweep of backend authorisation and data-isolation fixes landed, and analytics page-view capture stopped recording single-use links — password-reset, email-verification and rescue-invitation tokens — that could otherwise be read back from the analytics store.

AdoptDontShop 31 Jul 2026

Admin data exports secured against formula injection.

CSV files downloaded from the admin panel now neutralise formula characters in user-controlled fields — names, rescue names and similar data beginning with =, +, - or @ are escaped before download, so an export opens safely in Excel or Google Sheets without executing embedded content.

AdoptDontShop 28 Jul 2026

CI supply-chain hardening: fork-PR release bypass closed; deploy tokens scope-checked.

A fork pull request could previously satisfy the release gate and reach the container-publishing jobs with registry credentials in scope; the workflow now verifies a run originated from a push on this repository before any secret is accessed. The deploy and rollback pipelines also began verifying that the container-registry token carries only the access it needs before every release, failing loudly at the CI layer rather than on the production host.

AdoptDontShop 25 Jul 2026

React Router v8; dependency security sweep to zero high-severity.

All three frontends migrated from React Router v7 to v8, resolving two advisories with no v7 fix — a route-matching denial-of-service and a server-side CSRF — with Node.js updated to 22.23.1. A wave of dependency advisories was cleared across the week (brace-expansion, js-yaml, shell-quote, protobuf.js, DOMPurify, fast-uri and the OpenTelemetry Jaeger propagator), taking the automated advisory audit to zero high-severity findings.

AdoptDontShop 21 Jul 2026

Rescue event adoption attribution; real-time flood protection; GDPR records completed.

Rescue event analytics now attribute adoptions that followed an event — the “adoptions from this event” figure had always read zero because the cross-service link was missing. Unauthenticated connection attempts to the real-time gateway are rate-limited per IP before any token check runs, so a connection flood can’t consume backend capacity. Separately, the GDPR Record of Processing Activities was completed with sub-processor and data-location detail.

AdoptDontShop 19 Jul 2026

Distributed-tracing coverage completed.

OpenTelemetry instrumentation was extended to the content service, completing end-to-end trace coverage across every microservice — a single request can now be followed across service boundaries from the API gateway down to the database.

AdoptDontShop 18 Jul 2026

Security hardening day: 2FA setup, the edge and infrastructure.

The pending authenticator secret created during 2FA setup is now stored server-side, closing an attack that could lock the real account holder out. Sign-in responses for locked, suspended or deactivated accounts are made indistinguishable from a wrong password until the correct one is supplied, closing a user-enumeration path, and a 2FA-confirmation replay was closed. Invitation acceptance is rate-limited. At the edge: a strict Content-Security-Policy for the single-page apps, Socket.IO connection rate limiting, fail-closed CORS, HSTS and event-URL validation (javascript: and data: links rejected), with error and URL handling tightened so responses don’t leak internal detail. On infrastructure, production image digests were pinned and CI workflow-injection vectors closed.

AdoptDontShop 17 Jul 2026

2FA backup codes shown once; regeneration requires a live code; unverified-account oracle closed.

Backup recovery codes are now revealed exactly once in a confirm-before-dismiss panel, and regenerating them requires a valid current authenticator code — a stolen browser session alone can no longer replace the recovery path. Separately, submitting a correct password for an unverified account no longer bypasses the failed-attempt counter, closing a path that revealed whether a password was right before the account was verified.

AdoptDontShop 16 Jul 2026

2FA backup-code use made race-safe.

Consuming a two-factor backup recovery code is now atomic, so the same code can’t be accepted twice by two simultaneous sign-in attempts.

AdoptDontShop 15 Jul 2026

Session tokens moved to HttpOnly cookies.

Authentication tokens no longer live in browser localStorage — they’re held in HttpOnly, server-set cookies that JavaScript cannot read, removing the class of credential theft where a cross-site-scripting flaw silently exfiltrates a token. Any legacy tokens left in localStorage are purged on the first load after deployment.

AdoptDontShop 14 Jul 2026

CSRF protection groundwork; 2FA recovery codes; authenticator secrets encrypted at rest.

The gateway now issues and validates CSRF tokens for state-changing requests — the foundation for the move to cookie-based sessions. Accounts with two-factor authentication receive single-use recovery codes at enrolment, and the stored TOTP secrets that back the authenticator app are now encrypted at rest (AES-256-GCM), so a database exposure can no longer yield usable offline bypass codes.

AdoptDontShop 9 Jul 2026

Security: event data isolation, GDPR deletion and role escalation all patched.

A scoping gap in the events system meant rescue staff with event-read access but no linked rescue could inadvertently see attendee names and emails belonging to other organisations’ events; all event endpoints now enforce strict per-rescue isolation. A regression introduced by an earlier database migration had caused account-deletion requests (GDPR erasure) to fail silently, leaving personal data in place and sessions valid; deletion now completes correctly across all associated data. A gap in the admin user-update path allowed admin accounts to escalate their own or others’ roles to super-admin level without the correct authorisation checks; role changes now require the same strict guards as account creation.

AdoptDontShop 1 Jul 2026

API reliability restored; session security hardened; cold-start errors fixed.

A sweep of the API gateway resolved schema issues that were causing list endpoints to mis-serialise data, some DELETE and POST routes to reject valid requests, and the top-picks endpoint to return malformed responses — all gateway tests now pass. Refresh tokens are now stored as one-way hashes; a database exposure can no longer be used to impersonate an active session. The adopter portal, rescue dashboard and admin panel no longer return errors for around 40 seconds after a cold boot — all three now wait for the API gateway to become healthy before serving.

The rescue dashboard analytics page now shows real-time figures for adoption trends, application status, pet performance and top breeds, replacing the placeholder data that had been there since launch. Separately, account profile changes that were silently failing due to a routing mismatch now save correctly.

AdoptDontShop 29 Jun 2026

Saved analytics reports; adoption policy fix; application security hardening.

Rescue analytics reports can now be run to produce live figures, previewed, scheduled for recurring delivery and shared with team members. Saving changes to a rescue’s adoption policy on the Settings page no longer returns an error. Adoption applications now derive the applicant’s identity exclusively from the authenticated session — a body-level override that could previously be used to submit an application as a different user has been removed.

Operating principles · Journal

How this page is kept honest.

Within 24 hours

Every shipped feature gets a changelog line within twenty-four hours of going live.

Customer-facing language

Written for the people who use the product, not the engineers who built it. No commit-message jargon.

Workflow-breaking only

Bugs noteworthy enough to break a workflow get listed. Trivial fixes don’t clutter the page.
