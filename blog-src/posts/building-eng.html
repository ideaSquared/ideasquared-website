Why it exists

With shipper and Agent Idea in place, a working setup meant Node, pnpm, git, the GitHub CLI, two more CLIs, a GitHub sign-in and every repo, each with its own dependencies. Written down, that is a long page nobody follows twice the same way. So we made it one command:

curl -fsSL https://raw.githubusercontent.com/ideaSquared/eng/main/install.sh | bash

Windows gets the same thing through PowerShell. The installer only installs what is missing and never overwrites your own setup, so it is safe to run again. Then eng setup signs you in to GitHub, installs ship and idea, clones every repo you can see and installs their dependencies. eng update keeps it all current, and only ever pulls a clean checkout of the default branch, so it never touches work in progress.

The eng app

On 14 November, the same day as the installers, eng on its own became a themed menu over everything: what is live in every product, deploys, sanitised logs, failed runs, and setup and doctor. Each choice runs the real command, then brings you back to the menu. eng theme adds a matching terminal colour scheme and prompt, including for cmd.exe through Clink.

The fiddly part was handing the terminal over. The menu owns the keyboard. When it runs ship or idea, those need the keyboard instead, and then the menu needs it back. Three fixes on 15 November dealt with typed text not showing, a key press going to the wrong program, and “Press any key” not waiting.

Staging or production, fixed for the session

Also on 15 November: every eng session now starts in staging. To work in production you start the session that way, see a full-width red warning and type production. There is no switching mid-session, so a stray command can’t hit the wrong environment. ship still asks for the product name on a production deploy; eng never skips that.

Changing our minds in public

eng ops runs each product’s admin commands from one place. For AdoptDontShop, the first version on 15 November reached the server through an SSH tunnel, and eng setup created an SSH key for each engineer and added it to GitHub. Later that day we switched to plain HTTPS and removed the key step. Fewer moving parts, and nothing to set up per person.

On 21 November, review found that eng ops sent each product a GitHub token with more access than it needed. It now accepts only a token limited to reading team membership, and eng doctor and eng setup walk you through making one.

Standards and the long tail

On 22 November eng became home to the engineering standards every ideaSquared repo follows, by type of repo, including the frontend rules for accessibility. The same day eng itself met them: Node 24, linting, Conventional Commits, tagged releases, and CI that installs the packed CLI and runs it.

The rest was the long tail of real machines. eng doctor now finds stale copies of a CLI earlier on your PATH, which made an update look like it had failed. And on 23 November eng learned to set up a Python repo, with its own virtual environment, and to repair one that is half made.

What we learned

  • Safe to re-run is the whole feature. An installer you are scared to run again is one you won’t run when it matters.
  • Make the dangerous choice once, at the start. Fixing the environment for a session is simpler than checking it on every command.
  • Undo early. The SSH tunnel lasted a few hours. Dropping it the same day was cheaper than living with it.
