What review found: three security fixes in one day.

On 21 November review found a token sent too widely, log lines that slipped past the sanitiser, and a deploy tag that moved too easily. All three were fixed and tested that day.

  • By Alex Jenkinson, with support from Claude
  • 28 Nov 2026
  • 3 min read
  • Covers 21 Nov 2026

Three tickets, one day

On 21 November three fixes landed, one each in eng, agent-idea and shipper. They are ENG-1499, ENG-1504 and ENG-1511. Review found all three. The commits carry the ticket number and the fix, not the name of who reviewed, so we say no more than that.

This post is about the shape of the work, not the detail of each fix. The deeper stories have their own posts, linked below.

ENG-1499: a token wider than the job

eng ops talks to each product’s ops server. It sent the GitHub token from gh auth token, which carries the repo scope, to every product. The ops server replays the token to GitHub to check team membership. The commit describes the risk: a product server, or a compromised dependency of one, could collect repo-scoped tokens. eng ops find also sent the token to products the engineer was not a member of. We have no evidence that any token was collected.

The fix took three commits:

  • eng refuses a token with repo, workflow, write:*, admin:* and similar scopes, or whose scopes it cannot read. ENG_OPS_TOKEN supplies a token that can only read team membership;
  • that check then became an allowlist. Anything other than read:org is refused;
  • eng ops find contacts only products whose team the user is in, and ops URLs must be https (plain http only for localhost).

Refusing a token is no help if eng doctor keeps telling you to widen it. So doctor and setup now point you to ENG_OPS_TOKEN and give a link that pre-selects read:org. The tests are in test/ops.test.ts and test/checks.test.ts.

ENG-1504: shapes the sanitiser let through

agent-idea gives people and agents sanitised logs, so what slips through the sanitiser matters. On 21 November, two commits closed a list of shapes that passed through unchanged:

  • Stripe keys such as sk_live_… and rk_test_…, and variables ending in _KEY;
  • emails with non-English letters, and emails written with decomposed accents;
  • whole Cookie and Authorization values, not only the first word;
  • passwords with escaped quotes or spaces inside quotes.

Each shape is now a line in test/sanitise.test.ts, listing the exact text that must not survive. Both commits changed src/sanitise.ts and the test file together. The pattern is in every leak becomes a test.

ENG-1511: a deploy tag that moved on every push

Every product calls shipper’s reusable workflow through the v1 tag. Until this fix, a job triggered by pushes to shipper’s main could move that tag. The commit removes that job. Now v1 moves only through a manual run of the release workflow, inside a protected release environment. A verify job runs first and refuses a commit that is not on main, whose test check has not passed, or that is marked breaking since v1.

The same ticket changed the advice. shipper’s docs and its rollback template now tell products to pin the workflow, and shipper-ref, to an exact commit SHA. A workflow sample that a shipper command prints now shows the SHA form, and its test checks for it. On the same day, agent-idea pinned its own shipper workflows to a SHA. The full story is in pinning the deploy tool.

The process

The same steps ran three times. Review raised the problem. We wrote the fix as small commits, each named for the ticket. A test pinned the fix in place: a scope check, a leak line, a changed sample. It merged the same day, 21 November. None of these were big changes. The value was in the order: find it, fix it, write the test, then move on.

What we learned

  • Put the ticket number in the commit. A year from now, ENG-1499 tells you why eng ops refuses your token.
  • Fix the guidance as well as the code. A refusal that sends people to the old, wide token would have been a new bug.
  • Tests keep a fix fixed. Every one of these has a line that fails if the old behaviour returns.
  • Say what we do not know. We have no sign that any of these were abused, and we do not claim they were.
