Why move

Agent Idea’s Worker caches access answers in a KV namespace called ACCESS_CACHE. Until 22 November, its tests ran on Node and used a small fake of KV that we had written ourselves. A fake can only agree with what its author understood. The real binding, running in the real runtime, can disagree.

The change (90574d1, PR 28) did two things. The Worker tests now run inside workerd, with the bindings from wrangler.jsonc backed by local Miniflare storage. And the repo now has two Vitest projects, because not everything in it is a Worker.

Two projects, one config

The Worker code is in src/. The idea CLI, the MCP server and the packages under packages/ are Node programs. They should be tested on Node. So vitest.config.ts declares a project for each. This is the real file, trimmed:

import { cloudflareTest } from '@cloudflare/vitest-plugin';
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    projects: [
      {
        plugins: [cloudflareTest({ wrangler: { configPath: './wrangler.jsonc' } })],
        test: {
          name: 'worker',
          setupFiles: ['./test/setup-worker.ts'],
          include: ['test/access.test.ts', 'test/sanitise.test.ts', 'test/worker.test.ts', /* ... */],
        },
      },
      {
        test: {
          name: 'node',
          include: ['test/cli.test.ts', 'test/cli-process.test.ts', 'test/mcp.test.ts', 'packages/*/test/**/*.test.ts'],
        },
      },
    ],
  },
});

The worker project lists seven files: access, sanitise, the three log sources (Workers Logs, Loki, GlitchTip), GitHub Actions, and the Worker entry point. The node project lists the CLI, the MCP server and everything under packages/. Each project lists its files by name, so a new file runs nowhere until you add it.

A real binding, emptied each time

The plugin gives tests the bindings declared in wrangler.jsonc. Ours is one line: "kv_namespaces": [{ "binding": "ACCESS_CACHE" }]. Tests import it from cloudflare:workers. A tiny helper in test/kv.ts wraps that, and the tests no longer use the old fakeKv:

import { env } from 'cloudflare:workers';

export const accessCache = (): KVNamespace => env.ACCESS_CACHE;

export async function cachedKeys(kv: KVNamespace): Promise<string[]> {
  return (await kv.list()).keys.map((key) => key.name);
}

Storage that lasts between tests is how tests start to depend on each other. So test/setup-worker.ts runs before every test in the worker project and deletes every key:

beforeEach(async () => {
  const { keys } = await env.ACCESS_CACHE.list();
  await Promise.all(keys.map((key) => env.ACCESS_CACHE.delete(key.name)));
});

The tests changed in small ways. Where one used to read cache.store.size on the fake, it now awaits cachedKeys(cache) and checks the length. Where one seeded the fake with an old entry, it now calls cache.put(...). The test for “never stores the token” now reads every real key and value back and searches the lot.

The numbers

The commit body gives the counts: all 371 tests pass, 185 in workerd and 186 on Node, with no change to the Worker or the CLI. Two other files changed to support it: tsconfig.json gained the plugin’s types, and package.json gained @cloudflare/vitest-plugin as a dev dependency.

The rule for new tests

We wrote it into CLAUDE.md, where both people and Claude Code read it:

  • pnpm test runs both projects.
  • Worker code under src/ is tested inside workerd, with the real local ACCESS_CACHE binding.
  • The CLI, the MCP server and packages/ stay on Node.
  • Put a new test file in the project that matches the code it imports.

The commit also records which standards rule it satisfies, CF-15, and notes that CF-16 needed no change because the repo never used the older @cloudflare/vitest-pool-workers. The standards themselves are in one rulebook for every repo.

What we learned

  • Test in the runtime you ship to. A fake KV can only be as right as its author. The real local binding costs one config line.
  • Split projects by runtime, not by folder. Node programs stay on Node. Only the Worker needs workerd.
  • Reset shared storage before every test. One setup file keeps a real store from becoming hidden state.
  • Write the where-do-tests-go rule down. With named include lists, a file that is not listed does not run.
